# 웹 업로드 구현 계획

## 요구와 범위

[web-upload.md](../web-upload.md)를 구현합니다. 웹이 기본 입력 경로이며 신규도 `pending`으로 등록한 뒤 명시적 승인으로 번역합니다. 관리자 `process`는 파일명 규칙과 기존 일괄 등록을 유지합니다. 감시 명령·서비스는 제거합니다. 기능·배포 흐름 변경에 따라 기존 명세와 현재 구조를 갱신합니다.

## 구현 전략

- multipart를 스트리밍으로 파싱하며 파일 크기를 제한하고 `logs/.uploads/`에서 임시 보관합니다. 검증·등록 실패와 연결 중단에는 임시 파일을 정리합니다.
- Pipeline 공통 등록 경로에서 원본 불변 보관·차이 생성·잠금을 공유합니다. 웹의 문서 선택 검사와 rev 부여도 같은 잠금 안에서 처리합니다. `process`의 중복 입력 처리와 기준본 없는 개정 등록은 유지합니다.
- `/api/documents`, `/api/uploads`와 한국어 업로드 화면을 추가합니다. 신규 상세는 전체 번역 안내·확인 후 실행을 제공합니다. 기존 `auto_approved` 표시는 호환을 위해 유지합니다.
- Python·npm 설치와 실제 LLM 호출 없이 기존 도구로 검증합니다. `config.toml`, `uv.lock`, npm 의존성 파일은 수정하지 않습니다. 설치된 `python-multipart`만 직접 의존성으로 명시합니다.

## 검증

신규 업로드→대기→가짜 번역, 기존 문서 rev 증가·diff, 반려 번호 소비, 모든 거부 조건·잔여 파일·동시 요청·스트리밍 중단을 검사합니다. 기존 번역 재사용·출력 보존·실패 복구 회귀 테스트는 명시적 승인 흐름으로 갱신합니다. 프론트는 폼 전환·문서 선택 제한·rev 미리보기·성공 이동·오류·번역 확인을 검증합니다.
