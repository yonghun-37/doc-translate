# ADR-003: 독립 작업과 업로드한 중국어본의 번역 기억

## 상태

채택. 2026-11-17 사용자 결정 [job-model.md](../specs/job-model.md)를 구현합니다. [ADR-002](ADR-002-web-upload-and-explicit-translation.md)의 문서별 rev 등록·기준본 선택·관리자 CLI를 대체합니다. ADR-002의 스트리밍 수신·명시적 번역 실행과 [ADR-001](ADR-001-react-and-intranet-boundaries.md)의 라이브러리/React/연결 보안 경계는 유지합니다.

## 맥락

사용자는 한국어 원본·수정본과 이미 보유한 간체/번체 파일을 한 번에 올려 비교하고 번역해야 합니다. 기존 문서명·rev 이력은 이 입력 방식에 불필요한 순서 제약을 만들며 외부 번역본을 직접 재사용하지 못합니다. 기존 데이터는 비어 있으므로 이전·호환 계층은 필요 없습니다. 새 패키지·네트워크·작업 큐는 도입하지 않습니다.

## 대안

1. doc/rev에 외부 기준본 등록을 추가: 현재 요청에 필요 없는 이력/번호/최신본 검사와 복잡한 상태 전이가 남음.
2. 독립 작업과 업로드 파일로 기억 생성: 한 화면·한 작업에 입력과 판단 근거를 보관하고 이력 의존성 제거.
3. 모든 문장을 재번역하거나 의미 기반 매칭을 추가: 기존 번역 보존 요구에 맞지 않거나 추가 LLM·복잡도가 필요.

## 결정과 이유

- 2안을 채택합니다. `jobs/<id>` 안에 불변 inputs, review, output, status를 모읍니다. 등록은 검토 준비가 끝난 폴더 전체의 원자적 이동으로 공개합니다. 같은 파일시스템 내 jobs·logs가 필요합니다.
- DOCX·PPTX는 기존 engine/locations의 위치 그룹 정렬, XLSX는 읽기 전용 셀 주소·시트 대응으로 기억을 구성합니다. XLSX 추출 순서가 달라 동일한 순번 매칭을 사용할 수 없다는 사용자 실측을 반영합니다.
- 기존본은 언어별 선택이며 기억이 없는 언어는 전체 번역합니다. 같은 원문에 여러 번역은 최빈값, 동률은 첫 후보를 택합니다. 의미 추론은 하지 않습니다.
- 계획은 업로드 때 계산해 review/plan.json에 보관합니다. 조회할 때마다 Office를 다시 추출하지 않고, 사용자가 확인한 계획을 재시도까지 유지하기 위해서입니다.
- pending에서 바로 translating을 예약합니다. 기존 파일 잠금·BackgroundTasks를 유지하고, 결과 디렉토리를 두 언어 성공 후 공개합니다. 실패 시 출력 정리, translating 외 작업 삭제를 제공합니다.
- API는 `/api/jobs`, 화면은 `/`, `/new`, `/jobs/:id`, CLI는 serve·check-translator입니다. 기존 CLI/API·데이터 이전 코드는 제거합니다.

## 결과와 제약

입력·매칭 기억·검토·출력이 작업 안에서 독립되어 후속 이력 없이 재현할 수 있습니다. 삭제는 입력과 결과 전체를 제거합니다. 데이터는 Git에서 제외합니다.

위치/문자 일치만으로 번역 의미를 검증할 수 없습니다. DOCX 본문 문단 삽입/삭제가 뒤쪽 번호를 바꾸면 동일 위치 키로 잘못 대응할 수 있습니다. XLSX의 위치 이동·시트 순서 변경도 정확한 이름/주소가 없으면 신뢰하기 어렵습니다. 낮은 매칭률·샘플을 검토하도록 표시하지만 높은 매칭률도 의미 정확도를 보장하지 않습니다.

잠금은 직렬이며 영속 큐·프로세스 재시작 자동 복구는 없습니다. SIGKILL·정전 시 임시 폴더나 translating 상태, 상태 공개 전 output이 남을 수 있습니다. 서비스 중지 후 운영자가 복구합니다. inputs는 수정하지 않습니다.
