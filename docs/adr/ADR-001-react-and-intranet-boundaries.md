# ADR-001: React 검토 화면과 사내 LLM 연결 경계

## 상태

채택. 2차 작업의 사용자 제공 frontend-react·deployment-intranet 명세를 구현합니다. 기존 설계의 Jinja2 화면과 전역 원격 허용 설정을 대체합니다. 앞선 선택의 기록은 [1차 결과](../specs/initial-implementation/result.md)에 보존합니다.

## 맥락

검토 웹은 화면 갱신과 JSON 기반 시트 비교가 필요하고, 운영은 인터넷 없는 Linux·사내 LLM으로 이동합니다. 기존 원본 저장·번역 재사용·라이브러리 조립 구조는 유지해야 합니다. 실제 로컬 config.toml을 수정하지 않고 이전 설정도 읽어야 합니다.

## 대안

1. Jinja2 유지: 빌드 도구는 단순하지만 요청된 React 화면·JSON 계약을 만족하지 않습니다.
2. React와 별도 API/정적 서버: 별도 서비스·출처·배포 설정이 추가됩니다.
3. React 빌드물을 FastAPI에서 서빙: 개발에는 Vite, 운영에는 단일 로컬 웹 서버와 API를 사용합니다.

LLM 연결은 upstream 클라이언트를 그대로 쓰거나, HTTP/배치 구현을 교체하거나, 요청 경계만 서브클래스로 보완할 수 있습니다. 설치된 docutranslate는 verify=False 클라이언트를 만들므로 환경변수만으로 인증서 검증 요구를 충족하지 못합니다.

## 결정과 이유

- 3안을 선택합니다. API를 Pydantic 모델로 고정하고 React가 daff JSON 행을 텍스트로 렌더링합니다. 사용자가 지정한 패키지를 유지하며 HTML 삽입을 피합니다.
- `allowed_hosts`를 정확한 호스트 목록으로 사용하고 localhost는 항상 허용합니다. 이전 `allow_remote=true`는 경고를 남기고 최종 base_url 호스트 하나만 추가합니다.
- 요청 직전 서브클래스에서 인증서 검증 SSLContext·프록시 정책을 적용한 httpx 클라이언트를 사용합니다. 공급자 요청·응답·재시도 코드는 docutranslate에 남깁니다. 라이브러리 파일을 수정하거나 복사하지 않습니다.
- JSON 배열 계약과 json_object 강제가 충돌하므로 json_mode=false를 기본으로 둡니다. 근거는 2026-11-17 사용자 실측(비활성화 후 12/12 성공)입니다.
- 로그에 임의 예외 메시지를 남기지 않고 구조적 오류 종류·안전한 요약을 남깁니다. 라이브러리 경고/오류는 레벨만 보존합니다.

## 결과와 제약

SPA 빌드 단계와 dist 반입이 필요합니다. Python wheel만으로는 프론트가 포함되지 않습니다. upstream의 비공개 추출·요청 경계에 의존하므로 라이브러리 버전 변경 시 위치·TLS 경계 테스트가 필요합니다. 검증 클라이언트는 요청 단위로 생성되므로 연결 풀을 배치 전체에서 재사용하지 않습니다. 현재 요구를 넘어선 전역 monkey patch나 라이브러리 포크는 도입하지 않습니다.

원문을 포함할 수 있는 상세 예외를 버리므로 일부 문제의 내부 메시지는 사후 로그에서 복원할 수 없습니다. 실제 LLM·TLS 체인·Office 렌더링은 운영 시험이 남습니다. 오프라인 캐시 부족으로 uv.lock 생성도 아직 미완료입니다.

후속 결정: [ADR-002](ADR-002-web-upload-and-explicit-translation.md)는 이 웹·연결 구조를 유지하며 입력 감시를 웹 업로드와 명시적 번역 실행으로 전환합니다.
